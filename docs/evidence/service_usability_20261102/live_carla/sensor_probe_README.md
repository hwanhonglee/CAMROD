Measurements:

The observer also uses wall time. Each sample preserves its declared domain, original header stamp, both wall/simulation clock readings at receipt and observation, `/clock` receipt age and independent monotonic receipt age. Missing/stale simulation clock makes raw source age unavailable; timestamp magnitude never chooses a domain.
- Per-frame and per-case **shadow** radar-only / guard-only / both high-cost-cell overlap of the native front body corridor. Missing/stale/invalid/TF-pending input is unavailable. Unknown raster background is retained separately: **NO_HIT does not mean FREE/CLEAR**. Raw occupied/unknown counts are saved before TF; a newest-only pending grid can obtain its exact-stamp transform on later spins for at most .35 s. This is an input comparison, **not final-gate isolation, a commanded stop test, detection certification or a pass verdict**. Gate state is recorded independently. Real gate-mode comparisons remain root's separately authorized operation.

Important limits:

- Historical CARLA LiDAR mount is `(0.76336, 0, 0.59538)`, 16 channels, 120° horizontal and −25°..10° vertical FOV. Low close objects can lie below the rays; lack of a return is not evidence that a filter rejected it.
- The inspected CARLA nonground filter has **no radial 0.8 m minimum**: `0.8` is ground-seed tolerance. It uses `x>=0` ROI, ≥8 cm above fitted ground, and a measured self-return mask at `x=.40..1.31`, `|y|=.59..95`, `z=−.57..18` in LiDAR coordinates. A genuine overlapping return can be removed. Source: old `camrod_carla_adapter/config/carla_lidar_filter.yaml` and `lidar_filter.py`.
- Front radars are narrow 15° beams at `x=.62787,y=±.11005,z=.33378`; sensor range differs from body clearance. Do not equate 30 cm radar range to 30 cm bumper clearance or claim all narrow objects are observable.
- CARLA's physical mesh bbox and the native calibrated guard body can differ. Both are logged; no transform/calibration is silently changed. The grid-overlap metric includes half a grid cell for raster quantization and is not the final controller's corridor calculation.
- A no-owned-actor baseline is not proof that the map has no existing obstacles. Pair these logs with actual scene/browser evidence; do not label a real roadside object as a false positive solely from a nonzero cell.

Read-only browser/physical capture tools already available in the old virtual workspace: `tools/capture_live_navigation_state.py`, `scripts/virtual_carla/capture_ui_evidence.sh`, and `docs/evidence/virtual_carla/admin_reset_live_20261026/tools/{observe_live.py,capture_context.py}`.

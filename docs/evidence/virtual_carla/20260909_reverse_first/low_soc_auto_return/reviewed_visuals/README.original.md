# 저 SOC 자동 복귀 — 가려진 준비 구간을 제외한 실제 녹화 파생 자료

[주행 GIF](actual_motion_preparation_excluded.gif) · [실제 5장 요약 PNG](actual_contact_sheet_5_panels.png) · [프레임 대응/해시/명령 기록](derivation_manifest.json)

원본은 [desktop](../desktop/)에 그대로 남겨 두었다. 첫 준비 장면에서 VS Code가 CARLA 창을 가려, **그 준비 구간만 선택에서 제외했다.** 가려진 부분을 모델 이미지로 채우거나 다른 화면으로 교체한 것이 아니다. 실제 저배터리 긴급 알림과 화면의 시계는 지우거나 바꾸지 않았다. 새로운 주행, UI 조작, AI 이미지 생성은 없다.

- GIF: 기존 59프레임 중 0–9번(0부터 계산)을 제외한 49프레임, 1920×1070, 6.12초. 원본 GIF에서 제외한 재생 시각은 `[0.00, 1.25)`초이다.
- PNG: 기존 6장 contact sheet의 2–6번째 패널을 그대로 잘라 개별 PNG 5개와 3840×3342 요약본으로 만들었다. 부가 원영상 시각 표시는 원래 화면 바깥 검은 여백에만 넣었다.
- RGB 검증: 파생 GIF 49개 전체 프레임과 원본 retained 프레임이 픽셀 단위로 일치한다. 개별 PNG 5개도 원본 crop과 픽셀 단위로 일치한다. 입력 5개 파일의 SHA-256은 작업 전후 동일하다.
- 직접 시각 검토: 새 GIF의 첫 화면은 CARLA와 Robot UI이며 VS Code가 없다. 5장 요약본의 실제 긴급배터리 알림과 마지막 충전 화면은 보존되어 있다. 이는 시각 자료 검토이며 별도의 임무 성공 판정을 추가하지 않는다.

## 원영상 시각 대응

원본 MP4는 기존 capture의 보존 정책에 따라 **이번 작업 이전에 이미 제거**되어 있었다. 따라서 원영상 시각은 보존된 `capture_manifest.json`, `exact_commands.txt`, `ffprobe.json`의 선택 명령과 5 fps → 8 fps 변환에서 복원했다. 삭제된 MP4를 다시 열어 검증했다고 주장하지 않는다. 실제 남아 있는 GIF/PNG에 대해서는 직접 디코딩과 픽셀 검증을 했다.

## 출처와 재현

- 파생 GIF SHA-256: `b2cbef8df62f9e99907dbf0c3c4e4ccde39f87e20b7d0922c660bfff4ada6a9a`.
- 요약 PNG SHA-256: `9f6de072a545c6b278c2457c891a7fc65bde2f8383369f1fef8ff5be944737d6`.
- [오프라인 파생 스크립트](derive_reviewed_visuals.py)는 FFmpeg만 사용하며 `-n`으로 기존 산출물 덮어쓰기를 거부한다. 이미 생성된 폴더에 그대로 재실행하면 의도적으로 멈춘다. 실제 실행된 인자 전체는 manifest의 `exact_commands_argv`에 보존했다.

이 자료만으로 센서 소유권, 충돌 유무, 안전 gate 상태 또는 임무 전체의 성공을 판정하지 않는다. 해당 수치 판정은 기존 저 SOC 시험 결과와 원본 관측 기록을 함께 확인해야 한다.

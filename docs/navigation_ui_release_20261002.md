# 공통 주행 UI 반영 내역 — 2026-10-02

## 배포 범위

공통 Robot UI 개선은 `develop` 및 그 커밋에서 만들 `v2.3.0`에 포함한다.
네비게이션은 시뮬레이터 전용 화면이 아니다. 기존 실차 플랫폼의 위치·경로·인지
입력을 읽어서 동일하게 표시하며, 기존 서비스 선택 화면을 유지한다.

이번 반영에서 시뮬레이터 연결, 전용 수동주행 패널, 수동 개입 후 재개 기능은
가져오지 않았다. 이 기능들은 별도 통합 브랜치에만 남긴다.
주행 명령·안전 게이트·조향 제어기·주차·도킹·배터리 정책도 변경하지 않았다.

## 이번에 추가로 반영한 코드

| 코드 | 반영 내용 |
|---|---|
| `navigationMath.js`, `RangerNavigationScene.js` | 연속 위치·방향 변화로 네 바퀴의 표시용 조향/회전을 개별 계산. 제로턴·크랩에서 시점이 로봇 회전을 가리지 않도록 보정 |
| `navigationAreas.js`, `navigationAreaVisuals.js` | 원본 지도 폴리곤의 캠핑사이트·드롭존 면/윤곽/이름 표시. 영역 안에 장식물을 배치하지 않음 |
| `DrivingDisplay.js/.css` | 기본 지도·미니맵에 서비스 영역을 유지하고 목적지를 강조. 이름 중첩 완화 |
| `driving_snapshot.py`, `ui_backend_node.py` | 기존 `camping_sites_yaml`, `drop_zones_yaml`을 시작 시 한 번 읽고 검증해 `base_map.areas`로 전달. 새 ROS 구독이나 제어 출력을 추가하지 않음 |
| `App.js` | 출차 실패 시 선택 복구, 주차/충전 대기 문구 구분, UI 검증용 요소 식별자 보강 |
| 관련 JS/Python 테스트 | 위치 지연·좌표계 변경·각 바퀴 회전·폴리곤 검증·화면 표시 회귀 검사 |

기존 기본 도로 표시, 녹색 경계선, 경로, 객체 크기/모양 표시, 로봇 GLB·앞/옆/뒤
도색·적재물, 정지 확인창, 기존 서비스/실증 기록 화면은 그대로 유지한다.
기능 변경 이유는 해당 코드의 영어 `HH_261002 - ...` 주석으로 남겼다.

### 표현의 한계

바퀴 애니메이션은 수신된 **차체 위치 기반 무미끄럼 운동학 추정**이다.
실제 휠 CAN 각도/RPM을 측정했다고 표시하지 않으며, 미끄러짐이나 정지 상태에서의
조향 선행을 증명하지 않는다. 오래된 위치를 외삽해 계속 움직이게 하지 않는다.
나무·관목 등 장식 배경은 실제 지형이나 센서 측정 장애물이 아니다.

- 프런트엔드 전체: 12개 suite / 224개 테스트 통과.
- UI Python 회귀: 687개 통과.
- Robot UI 프런트엔드 계약: 42개 통과. Python 합계 729개.
- `npm run build`: 성공, `main.b3a025f0.js`, `main.0afe7b1b.css`.
- 새 영역 데이터 전송은 읽기 전용이며, 전용 수동주행/재개 의존성은 제외했다.

이 결과는 코드·UI 빌드 검증이다. 전체 사이트 주행, 실차 검증 또는 수동 개입 후
자율 복귀 성공을 의미하지 않는다. 이 문서를 작성한 시점에는 새 태그/원격 push를
실행하지 않았다.

## 재검증 명령

저장소 루트에서 실행한다. 의존성이 설치된 개발 환경을 전제로 한다.

```bash
python3 -m pytest camrod_ui/test -q
cd camrod_ui/camrod_ui_robot/assets/frontend
CI=true node node_modules/react-scripts/scripts/test.js --watchAll=false --runInBand
npm run build
```

일반 CAMROD 빌드·실행 방법은 기존 프로젝트 안내를 사용한다. 이번 UI 변경을 위해
별도 시뮬레이터나 물리 차량 제어 플러그인을 설치할 필요는 없다.

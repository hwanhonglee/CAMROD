# Administrator reset: native CAMROD integration

<!-- HH_261026 - Distinguish native release validation from simulator observations. -->

이 문서는 2026-10-26 `develop` 릴리스 준비 과정에서 관리자 정지 초기화
기능을 기존 CAMROD 백엔드에 통합한 범위와 검증 한계를 기록합니다.

## 포함한 변경

- 기존 관리자 인증 정보로 보호되는 `GET/POST /api/admin/safety/reset`.
  읽기 요청은 상태만 조회하며, 실행에는 별도 확인과
  `{"confirm": true}`가 필요합니다.
- 현재 미션과 동작 제어기를 정지·취소한 뒤, Nav2의 실제 cancel-all
  응답과 정차 실측값 및 최신 제어기 상태를 확인하는 일회성 트랜잭션.
- 제어기의 `/control/cmd_vel_safety_gate/reset_recovery_hold` 호출.
  비상정지·장애물·장비 오류를 무시하지 않으며, 성공 후에도 정지를
  유지합니다. 기존 미션을 자동 재개하지 않습니다.
- 초기화 처리 중에는 기존 명령 접수 장벽과 engage/drive-enable 발행
  지점에서 재활성화를 차단합니다.
- 기존 `/platform/status`와 제어기 상태 구독을 재사용합니다. 관리자
  화면을 열기 위한 별도 상시 센서 구독이나 반복 초기화 작업은 없습니다.

## native 브랜치에 맞춘 통합

시험 브랜치의 백엔드 파일 전체를 복사하지 않았습니다. 기존
`develop`의 미션·충전·복귀·운행기록 처리 코드를 유지하면서 이번
초기화 기능에 필요한 부분만 이식했습니다.

제어기 heartbeat는 전용 내부 관찰값
`_admin_safety_reset_gate_observation`에 저장합니다. 메시지의
`stamp`와 수신 시각을 각각 확인하며, 누락·오래된 값·미래 시각·NaN은
최신 상태로 인정하지 않습니다. 선택적 브라우저 telemetry 활성 여부와
무관하게 기존 제어기 구독을 사용합니다.

CARLA 연결 코드, 시뮬레이터 수동주행 기능, 수동주행 후 미션 재개 기능,
가상환경 전용 속도·복구 파라미터는 이 통합에 추가하지 않았습니다.

## 검증과 한계

- 정책·HTTP API·실제 백엔드 메서드와 기존 정지 경로의 모의 회귀 시험:
  283개 통과. 물리 로봇으로 명령을 보내지 않는 테스트입니다.
- native 전용 회귀 시험은 heartbeat의 신선도, telemetry 비활성 상태의
  메시지 보관, 실제 cancel future 수집, 초기화 중 재활성화 차단을
  포함합니다.
- 전체 UI 테스트 및 native C++ 빌드·시험 결과는 해당 릴리스의 종합
  검증 기록을 기준으로 확인해야 합니다.

별도로 수행한 CARLA 장시간 장애물 시험은 당시 실행 중이던 시험
브랜치 바이너리에 대한 관찰입니다. 이 native 이식 바이너리를 같은
물리 조건에서 실행했다는 증거가 아닙니다. 시험에서는 장애물 제거 후
자연 재개되어, 실차에서 보고된 지속 정지 현상이 재현되지 않았습니다.
따라서 실차 문제의 원인이나 해결 완료를 입증했다고 해석하면 안 됩니다.

초기화 버튼은 소프트웨어 복구 상태를 정지 상태에서 정리하는 수단이지,
활성 장애물·비상정지·장비 오류를 우회하는 강제 출발 버튼이 아닙니다.
